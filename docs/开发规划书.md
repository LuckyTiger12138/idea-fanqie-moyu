# 番茄小说 IDEA 插件「摸鱼阅读器」开发规划书

> 版本：v1.0　编写日期：2026-11-13
> 代号：**TomatoReader4J**（TomatoReader for JetBrains）
> 参考项目：https://gitee.com/mamo1103/tomato-reader （Electron + Vue3 桌面版）

---

## 0. 摘要（一页看懂）

| 项 | 结论 |
|---|---|
| 一句话定位 | 在 IDE 右侧工具栏内置一个小说阅读器，等编译、等 review、等日志时无痛摸鱼，一键隐身 |
| 产品形态 | ToolWindow 阅读面板 + StatusBar 迷你进度条 + 可选的「伪装皮肤」 |
| 技术栈 | Kotlin + IntelliJ Platform SDK（2023.1+）+ Gradle IntelliJ Platform Plugin 2.x + Swing 渲染 |
| 后端策略 | **可插拔三后端**：公共代理 API（MVP）／自建中转（推荐长期）／官方签名 API（P2，成本最高） |
| 工期 | 单人 6~7 周；MVP（能读能存能隐身）**3 周**可跑通 |
| 最大风险 | ① 第三方 API 随时失效　② Marketplace 审核因版权内容被拒　③ Swing 大文本渲染性能 |

**核心判断（先说结论）**：

1. **不要把接口写死**。番茄小说没有官方开放 API，社区项目全部依赖「移动端私有接口 + 签名」或「别人搭的代理」，两者都不稳定。插件必须把 `ApiClient` 做成接口 + 多实现 + 可配置 BaseURL，换源不改业务代码。
2. **不要把 Electron 的能力直接平移**。参考项目里的窗口级半透明、置顶悬浮窗、系统托盘、全局热键，在 IDEA 插件里**做不到或做法完全不同**（Swing 无法控制宿主窗口透明度、插件不能抢全局热键）。第 1.2 节给了逐项替代方案，这是本项目最容易在实现阶段返工的地方。
3. **摸鱼体验比功能数量重要**。真正决定这个插件生死的是「一秒隐身」和「一眼看不出是小说」，不是书架能放多少本。
4. **默认私有分发**。带版权内容的插件走 JetBrains Marketplace 大概率审核不通过，规划里按「本地安装 + 私有更新源」为主路径，Marketplace 作为可选尝试。

## 1. 项目背景与目标

### 1.1 需求来源

开发者在 IDE 里的碎片等待时间（编译、依赖下载、CI 跑测试、等同事回消息）高度集中且难以利用。切浏览器看小说会留下痕迹、打断心流、且容易被发现。把阅读器放进 IDE 内，可以做到：不切窗口、不留浏览器历史、随时一键收起。

### 1.2 参考项目拆解与平台差异

参考项目 `tomato-reader` 是 **Electron + Vue3 + TypeScript** 桌面应用，核心链路为：搜索 → 详情 → 目录 → 阅读，章节内容三级缓存（内存预取 → 磁盘 JSON → 网络）。

| 参考项目能力 | 其实现方式 | IDEA 插件中的做法 | 差异/风险 |
|---|---|---|---|
| 窗口级半透明、毛玻璃 | BrowserWindow `opacity` + CSS backdrop-filter | **不可行**。插件无法修改 IDE 宿主窗口透明度 | 降级：面板背景色半透明（`setOpaque(false)` + 主题色），或用 JCEF 内做 CSS 毛玻璃，视觉上只影响面板区域 |
| Mini 置顶悬浮窗 | 独立 BrowserWindow + `alwaysOnTop` | 用 **StatusBarWidget** 做一行迷你信息（第 x/y 章）；或用 `JBPopup` 悬浮小窗（不置顶、随 IDE） | 不能跨应用置顶，这是平台硬限制 |
| 系统托盘 | Tray API | 用 **Notification**（气泡）+ 状态栏图标替代 | 无托盘 |
| 全局热键（老板键） | globalShortcut | 只能用 **IDE 内快捷键**（Keymap Action），IDE 失焦时无效 | 需在文档中明确告知用户 |
| CSS 主题导入（.css 文件） | 运行时注入 CSS | 改为 **JSON/Properties 主题包**（颜色、字号、行距、字体） | 不能执行任意 CSS，安全上也更好 |
| API 由主进程代理（绕 CORS） | ipcMain + node fetch | 插件内直接 HTTP，**无 CORS 概念** | 更简单 |
| 章节磁盘缓存 | `app.getAppPath()/cache` | `PathManager.getSystemPath()/tomato-reader/cache` | 放系统目录而非项目目录，避免污染仓库、避免被 git 提交 |
| 阅读进度记忆 | localStorage | `PersistentStateComponent`（XML） | 天然持久化，随 IDE 配置漫游 |
| 字号/字体/主题 | CSS 变量 | Swing `StyleConstants` + `Font` | 需要自己写样式层 |

> **结论**：业务链路（搜索/目录/正文/缓存/进度）可 1:1 平移，**视觉与窗口相关能力约 40% 需要重新设计**。

### 1.3 产品目标与非目标

**目标（v1）**
- G1：在 IDE 内完成「搜书 → 加入书架 → 读章 → 记住进度 → 下次续读」闭环，全链路 ≤ 3 次点击。
- G2：任意时刻 **1 个快捷键（或 1 次 Esc 双击）在 100ms 内让阅读内容从屏幕上消失**，且不打断编辑。
- G3：断网可读已缓存章节；换电脑后书架与进度可随 IDE 设置同步（可选）。
- G4：对 IDE 启动时间与内存影响可控（增量内存 < 80MB，启动无感加载）。

**非目标（v1 明确不做）**
- 不做付费章节破解、不做签名算法逆向绕过（合规红线，见 2.3）。
- 不做整本导出、不做二次分发、不做离线全书库。
- 不做听书、不做漫画/短剧（接口虽支持，但优先级低于核心阅读体验）。
- 不追求多书源聚合（v2 再议）。

### 1.4 用户画像与使用场景

| 场景 | 触发点 | 期望行为 |
|---|---|---|
| 等编译 | Build 面板转圈 30s | 侧边栏已在当前章节，滚两屏就回去 |
| 等 CI / 等 review | 提了 PR 卡住 | 状态栏显示进度，点一下展开面板 |
| 开会/同事走近 | 有人靠近工位 | 老板键 → 面板消失，光标已在编辑器里 |
| 午休 | 不想开浏览器 | 字号放大、自动滚动 |

## 2. 可行性分析

### 2.1 数据源现状（最关键的技术前提）

番茄小说**没有官方开放 API**。现有社区方案分三类：

| 方案 | 代表实现 | 鉴权方式 | 稳定性 | 落地成本 | 本项目定位 |
|---|---|---|---|---|---|
| **A. 公共代理 API**（swagger 风格） | 参考项目 tomato-reader 所用服务 | 域名级授权，请求头带凭据；未授权返回 403 | 低（单点，随时挂） | 极低 | **MVP 首选**，一天接通 |
| **B. 自建中转服务** | PyFQWeb、fanqie-api 等自部署 Flask/Node 服务 | 自建，无鉴权或简单 token | 中高（自己控制） | 中（需一台服务器/本机进程） | **推荐长期方案**，插件只填 BaseURL |
| **C. 官方移动端接口直连** | 各类 downloader 项目 | `device_register` 注册设备 → 请求头携带 `X-Argus`/`X-Gorgon`/`X-Khronos`/`X-Ladon` 等签名 + `Cookie`；参数含 `aid`、`device_id`、`iid` 等 | 中（随 App 版本变化） | 高（签名算法逆向 + 设备池） | **P2 可选**，仅在有明确需求时做 |

**接口对照（A/B 方案，与参考项目一致）**

| 功能 | 端点 | 关键参数 | 返回要点 |
|---|---|---|---|
| 搜索 | `GET /api/search` | `query`、分页偏移（≈(page-1)*10）、`tab_type=3`（书籍） | `book_id`、`title`、`author`、`cover`、`abstract` |
| 书籍详情 | `GET /api/detail` | `book_id` | 元数据 + 章节数 + 状态 |
| 目录 | `GET /api/book`（参考项目）／`/api/catalog`、`/directory/all_items`（社区通用） | `book_id` | `item_id` 列表 + 章节标题 |
| 正文 | `GET /api/content` | `item_id`、`text_mode=false`、`image_mode=false` | HTML/文本混排正文，需清洗 |
| 批量正文 | `GET /api/multi-content` | `book_id` + 逗号分隔 `item_ids` | 用于整段预取 |
| 授权状态 | `GET /api/auth/status` | 无 | 200 已授权 / 403 未授权 |

> ⚠️ **字段名与路径必须以 P0 阶段实测为准**（用浏览器/HTTP 客户端打一次，落一份 `docs/api-snapshot.json`）。本规划书中的字段是社区通行版本，不保证与当前线上一致。**不做「凭记忆写死字段」的实现**，一切以抓包为准。

**技术结论**：插件侧只依赖一个极薄的 `TomatoApiClient` 接口 + JSON 反序列化，后端形态由用户在设置里选（公共 API / 自建 / 自定义 BaseURL）。这样 API 挂了用户能自己换源，插件不至于直接报废。

### 2.3 合规与法务边界（红线，必须写进 PRD）

本项目定位为**个人阅读辅助工具**，规划中明确以下边界，并在 README 与插件内「关于」页公示：

1. **只读取用户本可访问的公开章节**；不实现付费/SVIP 章节的绕过，不做签名算法的破解与分发。
2. **不内置任何第三方破解签名库**；方案 C（官方签名直连）仅在拿到合法授权或明确技术研究场景下评估，默认不启用。
3. **不提供整本导出、不提供二次分发能力**；缓存仅用于降低重复请求，建议 24 小时内自动清理（参考社区项目的版权条款）。
4. **不使用书名/内容做商业化**；插件免费、无广告、无付费墙。
5. **失败即降级**：接口 403/无授权时给出明确提示，不静默重试、不做规避性重试策略。
6. **企业环境提示**：README 中提示部分公司会对 IDE 插件做审计，使用者需自行评估。

> 上述边界同时是 **Marketplace 审核的防线**（见 10.2）。如果坚持上 Marketplace，需要把「内容来源为用户自配的第三方服务」写清楚，并去掉所有可能被判定为「帮助规避版权保护」的功能。

## 3. 总体架构

### 3.1 分层结构

```
┌──────────────────────────────────────────────────────────┐
│ UI 层 (ui)                                                │
│  ToolWindow 面板 │ 书架列表 │ 目录树 │ 阅读视图 │ 设置页    │
│  Actions（老板键/翻页/字号） │ StatusBarWidget │ 伪装皮肤    │
├──────────────────────────────────────────────────────────┤
│ 服务层 (service)  —— Application 级单例，生命周期随 IDE     │
│  ReaderService（当前书/章/进度） │ BookshelfService（书架）  │
│  ProgressService │ CacheService │ PrefetchService          │
│  SettingsService（持久化 + 变更广播）                       │
├──────────────────────────────────────────────────────────┤
│ API 适配层 (api)                                          │
│  TomatoApiClient（接口）                                   │
│   ├─ ProxyApiClient    公共代理 /api/*（MVP）              │
│   ├─ SelfHostApiClient 自建中转（BaseURL 可配）            │
│   └─ OfficialApiClient 官方签名（P2，默认关闭）             │
│  共用的：HttpEngine、RetryPolicy、ContentCleaner、错误映射  │
├──────────────────────────────────────────────────────────┤
│ 模型层 (model)  Book / Chapter / CatalogItem / ReadingPos   │
├──────────────────────────────────────────────────────────┤
│ 基础设施 (infra)                                          │
│  HttpClient(JDK) │ Json(kotlinx) │ PathManager 存储 │ 日志  │
└──────────────────────────────────────────────────────────┘
```

### 3.2 模块清单

| 模块 | 职责 | 对外关键接口 | 优先级 |
|---|---|---|---|
| `ui.toolwindow` | 面板承载、路由切换（书架/详情/阅读） | `ReaderToolWindowFactory` | P0 |
| `ui.reader` | 文本渲染、翻页、滚动、进度回写 | `ReaderPanel.render(Chapter)` | P0 |
| `ui.bookshelf` | 书架增删、最近阅读、搜索入口 | `BookshelfPanel` | P0 |
| `ui.settings` | BaseURL、凭据、主题、字号、缓存策略 | `SettingsConfigurable` | P0 |
| `service.reader` | 当前书/章状态机、加载与取消 | `openChapter(bookId, itemId)` | P0 |
| `service.cache` | 内存/磁盘两级缓存、清理、容量统计 | `get/put/clear/stats` | P0 |
| `service.prefetch` | 下一章（可配 N 章）预取 + 指数退避重试 | `schedule(bookId, nextIds)` | P1 |
| `service.shelf` | 书架持久化、排序 | `PersistentStateComponent` | P0 |
| `api.*` | 三后端实现 + 错误码映射 | `search/detail/catalog/content` | P0 |
| `action.*` | 老板键、翻页、字号、伪装切换 | `AnAction` | P0/P1 |
| `ui.statusbar` | 状态栏迷你进度 | `StatusBarWidget` | P1 |
| `ui.skin` | 伪装皮肤（注释/日志/JSON） | `SkinRenderer` | P1 |

### 3.3 关键设计决策（含备选与理由）

| # | 决策 | 选定方案 | 备选 | 理由 |
|---|---|---|---|---|
| D1 | 渲染技术 | **Swing `JTextPane` + 分段 `StyledDocument`**，JCEF 作为可选「富文本模式」 | 纯 JCEF | Swing 冷启动 < 30ms、零额外内存；JCEF 每次创建浏览器实例约 100-300ms 且占 50MB+。摸鱼场景触发频繁，启动速度优先 |
| D2 | HTTP 客户端 | **JDK `java.net.http.HttpClient`** | OkHttp / Apache HttpClient | 平台自带 OkHttp 但版本随 IDE 变动，打包自己的易冲突；JDK 客户端零依赖，且 IDE 2023.1+ 跑 JDK 17 |
| D3 | JSON | **kotlinx.serialization**（随插件打包，不依赖平台） | Gson（平台自带） | 平台 Gson 版本不可控；kotlinx 支持 `ignoreUnknownKeys`，接口加字段不崩 |
| D4 | 并发模型 | 平台 `AppExecutorUtil` + `CompletableFuture`，章节切换时 **取消旧请求** | 全量 kotlinx.coroutines | 减少依赖；但若已在用 coroutines，可只做取消传播 |
| D5 | 缓存位置 | `PathManager.getSystemPath()/tomato-reader/` | 项目目录 / 临时目录 | 不污染用户仓库、不进 git、随 IDE 卸载可清 |
| D6 | 后端选择 | **接口化 + 运行时切换**（见 2.1） | 写死单一 API | API 不可控是最大风险，必须留后路 |
| D7 | 状态持久化 | `PersistentStateComponent`（XML，application 级） | JSON 文件自管 | 平台原生支持、原子写、支持配置漫游 |

## 4. 功能规划

### 4.1 P0 / MVP（必须，第 3 周末可交付）

| 编号 | 功能 | 验收标准 |

| F-01 | 搜索 | 关键词回车出结果列表（书名/作者/简介），支持分页；空结果有明确提示 |
| F-02 | 书籍详情 | 展示封面/书名/作者/状态/简介/章节数；封面加载失败不崩 |

| F-09 | 缓存 | 内存命中 < 1ms；磁盘命中 < 20ms；缓存目录可清空、显示占用 |
| F-10 | 错误处理 | 网络失败/403/超时/JSON 异常 → 面板内友好提示 + 「重试」，不弹 IDE 异常对话框 |

### 4.3 差异化：摸鱼专属设计（本项目的灵魂）

> 竞品（浏览器、手机）不可替代的价值就在这里。建议把这一节当作独立需求评审。

1. **一秒隐身（Boss Key）**
   - 默认 `Ctrl+Shift+\``（可改）：同时执行 ① 隐藏 ToolWindow ② 焦点还给当前编辑器 ③ 恢复被阅读器抢走的滚动位置 ④ 可选「把面板内容替换成 Build 输出」。
   - 双击 `Esc` 作为第二触发（不离开键盘区）。
   - **100ms 内完成**，不做渐隐动画（动画会拖慢）。
2. **内容伪装皮肤**
   - `//` 注释皮肤：每段前加 `// `，等宽字体，行号栏可用假行号，视觉上等价于一个「注释了很多行」的 Java 文件。
   - StackTrace 皮肤：首行 `java.lang.NullPointerException: ...`，正文按 `\tat com.xxx.SomeClass.method(SomeClass.java:123)` 排版——熟人扫一眼只会觉得你在看异常。
   - JSON 皮肤：`{"content": "……"}` 包裹，用 IDE 的 JSON 高亮色。
   - Git Log 皮肤：`commit abc1234` / `Author: zhang.san` / 缩进正文。
   - 皮肤切换 1 个快捷键轮换。
3. **标题伪装**：ToolWindow 标题可改为 `TODO` / `Problems` / `app.log`（要检查是否与 IDE 现有 ToolWindow 重名，重名时禁用该选项）。
4. **静音模式**：全局关闭通知、关闭任何音效、禁用「新章提醒」气泡。
5. **频率克制**：不做「新章节更新提醒」「阅读时长统计排行榜」这类容易被发现的社交化功能（明确列入非目标）。
6. **不做的伪需求**：检测屏幕共享/远程会议状态并自动隐藏——插件无法可靠获取该状态，做了反而误判，明确不做。

### 4.4 Out of Scope（v1 不做，写清楚避免需求蔓延）

整本下载、EPUB/TXT 导出、TTS 听书、漫画/短剧、评论、多书源聚合、云同步服务端、AI 摘要、移动端联动。

### 6.3 API 适配层（可插拔的关键）

```kotlin
interface TomatoApiClient {
    suspend fun search(query: String, page: Int): List<Book>
    suspend fun detail(bookId: String): Book
    suspend fun catalog(bookId: String): List<CatalogItem>
    suspend fun content(itemId: String): String        // 原始正文（HTML/文本混排）
    suspend fun healthCheck(): AuthState               // AUTHORIZED / UNAUTHORIZED / UNREACHABLE
}

sealed class ApiException(message: String, cause: Throwable? = null) : Exception(message, cause) {
    class Unauthorized(val hint: String) : ApiException(hint)   // 403
    class NotFound(val what: String) : ApiException("资源不存在：$what")
    class Network(val cause: Throwable) : ApiException("网络错误：${cause.message}", cause)
    class Parse(val raw: String) : ApiException("响应解析失败")
}

object ApiClientFactory {
    fun create(settings: SettingsService.State): TomatoApiClient = when (settings.backend) {
        Backend.PROXY      -> ProxyApiClient(settings.baseUrl, settings.token)
        Backend.SELF_HOST  -> SelfHostApiClient(settings.baseUrl, settings.token)
        Backend.OFFICIAL   -> OfficialApiClient(settings)      // P2，默认禁用
    }
}
```

**正文清洗规则（`ContentCleaner`，必须单测覆盖）**
1. 剥 HTML 标签 → 实体反转义 → 保留 `<p>` 段落边界。
2. 丢弃空行、纯广告行（含「番茄小说」「本章完」「请记住本站」等关键词表可配置）。
3. 中文首行缩进两字符；英文段落不缩进。
4. 合并被硬换行打断的句子（上一行不以标点结尾且下行为短行时合并）。
5. 保留作者有意的分隔符（`* * *`、`——`）。

### 6.4 缓存与预取

**三级缓存**（对齐参考项目，但补上容量控制）：

| 层 | 介质 | 命中耗时 | 失效策略 |
|---|---|---|---|
| L1 | `ConcurrentHashMap<String, Chapter>`（上限 8 章，LRU） | < 1ms | 容量淘汰 |
| L2 | 磁盘 `<system>/tomato-reader/cache/<bookId>/<itemId>.json` | < 20ms | 24h TTL + 总容量 200MB LRU |
| L3 | 网络 | 200~2000ms | 成功后异步写回 L2 |

**预取策略**
- 当前章渲染完成后触发 `PrefetchService.schedule(nextN)`，N 默认 1（可配 0~3）。
- 失败退避：3s / 6s / 12s，最多 3 次，之后放弃并在底栏标灰。
- 取消：用户切换书籍时，取消所有在飞请求（`CompletableFuture.cancel(true)` + 请求级 `Abortable`）。
- 并发上限：全局 2 个在飞请求（避免被风控/限频）。

### 6.5 大文本渲染性能方案（P0 阶段必须先验证）

`JTextPane` 一次性插入 5 万字会卡 300~800ms 并造成滚动抖动。方案：

1. **分段插入**：按段落 `StyledDocument.insertString` 批量插入（每批 200 段），`document` 处于 `writeLock` 外不做 `revalidate`。
2. **延迟布局**：插入前 `setText("")` 并关闭 `autoscroll`，插入完成后统一 `setCaretPosition(0)`。
3. **超长章节降级**：> 5 万字启用「分段加载」（滚动到 80% 时追加下一段），或提示用户。
4. **复用组件**：面板常驻，切章只换 `Document` 内容，不重建 `JTextPane`（避免重复初始化耗时）。
5. **性能门槛**：5 万字渲染 < 150ms（P95），滚动帧率 ≥ 50fps，验收用 P0 的基准测试脚本卡。

### 6.7 线程模型

- **绝不能**在 EDT 上做网络或大文本处理；所有请求 `AppExecutorUtil.getAppExecutorService()`。
- 章节切换：`ReaderService` 持有 `volatile` 当前请求句柄，新请求先 `cancel` 旧的，回包时校验 `requestId` 防串章（这是最容易出的 bug）。
- 长任务用 `ProgressManager.run(Task.Backgroundable)`，让用户可取消、可看进度（也符合平台规范）。

### 6.8 平台合规（审核与规范）

- 所有 UI 更新走 `ApplicationManager.getApplication().invokeLater`。
- 不阻塞 `StartupActivity`（书架在首次打开面板时懒加载）。
- 不静态持有 `Project`/`Editor` 引用（内存泄漏红线）。
- 所有用户可见文案走 `ResourceBundle`（i18n 预留，`plugin.xml` 中 `resource-bundle`）。
- ToolWindow 默认不自动打开（`available` 而非 `visible`），避免用户第一次装完 IDE 就弹出来。

### 10.1 三条路径（按推荐度排序）

| 路径 | 做法 | 适用 |

### 10.2 Marketplace 审核风险与预案

- **风险**：涉及第三方版权内容获取的插件，审核可能以「侵犯知识产权/协助规避访问控制」为由拒绝。
- **降低被拒概率的做法**：插件自身**不内置任何 API 地址**（默认空，必须用户自行填写）、不内置解析规则、不提供下载/导出、README 明确「本插件只是通用阅读器前端，内容来源由用户自行配置」。
- **预案**：若被拒，转 A/B 路径，不投入反复申诉成本。

### 10.3 版本与文档

- 语义化版本；`plugin.xml` 的 `<change-notes>` 保留最近 3 个版本。
- 必写文档：`README.md`（安装/配置/快捷键/免责声明）、`docs/API.md`（接口快照与字段说明）、`docs/SKIN.md`（皮肤开发指南）、`LICENSE`。

## 12. 后续演进（v2 设想，不作为承诺）

1. **本地 TTS 听书**：接系统语音或本地 Edge-TTS，通勤场景延伸。
2. **多源聚合**：抽象 `BookSource` 概念，支持用户自建源（借鉴阅读 App 的书源规则），彻底摆脱单一 API 依赖。
3. **AI 辅助**：章节摘要、人物关系图（调用 IDE 内已有 AI 能力，不额外传正文到第三方）。
4. **团队书架**：把「最近在读」做成可分享的只读列表（注意隐私，默认关闭）。
5. **JCEF 富文本模式**：支持更精美的排版与自定义 CSS 主题（对齐参考项目的主题生态）。
